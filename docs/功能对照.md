# 功能对照：XScript 与 AScript

这份清单把 AScript 官网（ascript.cn）列出的 Android 功能和 XScript 当前的实现逐项对照，用来决定下一步做什么。

对照依据有两个：

- **AScript 侧**：官网 sitemap（2026-10-01）中的 Android API 文档和服务页面。
- **XScript 侧**：本仓库的代码。

AScript 兼容层在 `android/python-runtime/ascript/`，XScript 自有 API 在 `android/python-runtime/xscript/`。

状态说明：

| 标记 | 含义 |
| --- | --- |
| ✅ 已有 | 能用，接口和 AScript 兼容 |
| 🟡 部分 | 能调用，但实现方式不同或功能缩水（见备注） |
| ⛔ 空壳 | 只有接口，调用会报 `NotImplementedError` |
| ❌ 没有 | 接口也没有 |
| 🚫 不做 | 有意不做（原因见备注） |

在「需要？」一列标上你的判断（要 / 不要 / 以后），我按这个排下一批。

## 7. 真机验证

网页 IDE 的工程/文件管理（新建工程、文件、文件夹，删除及 400/404/409 错误）、目录树和 Python 语法高亮已于 2026-10-14 在 Android 模拟器（emulator-5554，Android 17，arm64）上验证，尚未在真机上验证。

**已知问题（2026-10-14）**：在 Android 17 的 16KB 页面模拟器（Medium_Phone，`ps16k` 镜像）上，内置 numpy 无法导入（`dlopen failed: library "libopenblas.so" not found`），OpenCV 随之不可用。推测原因是 Chaquopy 17 的 numpy 1.23.3 / OpenBLAS 旧 wheel 没有按 16KB 对齐。**设备验证（2026-10-14）**：新建 4KB 页面的 API 34 模拟器（`API34_4k`，arm64 google_apis）后，内置 numpy 1.23.3 / OpenCV 4.5.1 可以正常导入，运行时测试 `test_cvfont`（13）、`test_image`（19）、`test_vision`（11）、`test_gp_compat`（10）、`test_vlm_compat`（10）、`test_ml`（17，其中 2 个被测试自身跳过）、`test_ascript_compat`（9）、`test_selector`（16）、`test_resources`（3）在设备上全部通过；其中发现并修复了一个只在 OpenCV 4.5.1 出现的透明模板找图问题（见 CHANGELOG）。16KB 页面设备上 numpy 仍然不可用，结论不变；4KB 页面的真机没有测过，`test_pip` 以及真实模型推理没有在设备上跑。

下面这些已经写完并通过单元测试，但还没有在真机上完整跑过：

- 云控连接新后台、远程操控、运行日志
- 卡密激活和复核
- 热更新下载并替换工程
- 代码保护打包的 App 运行
- 脚本崩溃上报和告警推送
