# 更新文档截图

文档里的截图都放在 `docs/images/`。界面有明显变化时（布局、文案、颜色）要一起更新截图，并在 PR 里说明。

## 规则

- **只用演示数据和一次性设备**：在专门用来截图的模拟器上截（不要用存有自己数据的手机或模拟器），工程用「每日签到」这类演示工程，后台用演示数据。
- **不要露出隐私**：配对码、令牌、私人路径、真实 IP、真实账号都不能出现在截图里。提交前把每张图都看一遍。
- **浅色和深色成对**：已经有浅色 / 深色两张的截图，两张一起更新，尺寸保持一致。桌面端统一用 `--size 1180x760`。
- **文件名不变就不用改文档**：同名覆盖即可。新增或改名时，记得在 Markdown 里引用它。
- **没被引用的图会让 CI 失败**：`scripts/check_docs.py`（每个 PR 和每周都会跑）要求 `docs/images` 里的每个文件都被仓库中某处引用；删掉旧图，不要留着。

## 怎么生成

| 截图 | 生成方式 |
| --- | --- |
| 桌面端各页（`desktop-after-*.png`） | `cd desktop/app && python -m xscript_desktop --screenshot out.png --connect-adb <serial> --click-screenshot --theme dark --size 1180x760`（`--theme` 会真的去按侧栏的主题按钮） |
| 桌面端工程页（`desktop-projects-{light,dark}.png`） | 设备上放一个带子文件夹的工程「每日签到」，然后 `python -m xscript_desktop --screenshot out.png --connect-adb <serial> --run-js tools/screenshot-projects.js --screenshot-delay 4 --theme light --size 1180x760`，深色把 `light` 换成 `dark` |
| 桌面端工程搜索（`desktop-projects-search-{light,dark}.png`） | 设备上放工程「每日签到」（几个文件里用到 `ocr_click`），然后同上，把 `--run-js` 换成 `tools/screenshot-search.js`、`--screenshot-delay 6`；用 `--data-dir` 指向临时目录，不碰自己的桌面端数据 |
| 桌面端连不上设备提示（`desktop-connect-error-{light,dark}.png`） | `python -m xscript_desktop --data-dir <临时目录> --screenshot out.png --run-js tools/screenshot-connect-error.js --screenshot-delay 6 --theme light --size 1180x760`，深色把 `light` 换成 `dark`；不需要设备 |
| 桌面端逐项检查连接（`desktop-connect-check-{light,dark}.png`） | 手机上先强制停止 XScript（`adb shell am force-stop <包名>`），然后 `python -m xscript_desktop --data-dir <临时目录> --screenshot out.png --run-js tools/screenshot-connect-check.js --screenshot-delay 9 --theme light --size 1180x760`，深色把 `light` 换成 `dark` |
| VS Code 插件（`vscode-run.png`、`vscode-debug.png`、`vscode-connect.png`） | `ide/vscode-extension/scripts/vscode-screenshots.sh`：真实 VS Code、隔离配置、模拟器上的演示工程，通过 DevTools 协议截图；`vscode-connect.png` 用 `XS_SHOT_NAMES=connect`，并先在模拟器上强制停止 XScript |
| 手机端（`phone-*.png`） | 在一次性模拟器上打开对应页面后 `adb -s <serial> exec-out screencap -p > docs/images/phone-xxx.png` |
| 桌面端截图状态卡片（`desktop-capture-lost-{light,dark}.png`） | 模拟器冷启动（系统录屏授权失效），关闭无障碍，打开 XScript，然后 `PYTHON_KEYRING_BACKEND=keyring.backends.null.Keyring python -m xscript_desktop --data-dir <临时目录> --adb <adb> --connect-adb <serial> --screenshot out.png --run-js tools/screenshot-capture-status.js --screenshot-delay 8 --theme light --size 1180x760`，深色把 `light` 换成 `dark`；空钥匙串后端保证不把配对码写进系统钥匙串 |
| PyCharm 连接检查（`pycharm-connect-check.png`） | 模拟器上打开 XScript 并 `adb forward tcp:9860 tcp:9860`，然后在 `ide/pycharm-plugin` 里 `./gradlew runIde -PrunIdeProject=<演示工程> -PrunIdeHeadlessConsent -PrunIdeScreenshotDemo=connect -PrunIdeScreenshotConnect=127.0.0.1:9860 -PrunIdeScreenshotOut=<目录>`，约 30 秒后得到 `<目录>/connect.png`（对话框）；只读取设备状态，不保存地址 |
| PyCharm 插件其余截图、网页 IDE、管理后台（`pycharm-*`、`ide-*`、`admin-*`） | 目前手动截图：演示工程 / 演示数据，窗口宽度和现有截图保持一致 |

### 用 `--run-js` 自动走到要截的页面

`--run-js FILE` 会在设备连上之后，把 FILE 里的 JavaScript 放到桌面端页面里执行，适合「先点几下再截图」的场景。写法参考 `desktop/app/tools/screenshot-projects.js`：

- 按文字找按钮再点（例如侧栏的「工程」、工程名、文件名），每一步之间轮询等待元素出现，不要写死等待时间；
- 脚本不要改设备上的数据（截图前需要的工程和文件提前在设备上准备好）；
- 配合 `--screenshot-delay` 给最后一步留出渲染时间。

## 提交前

```bash
python3 scripts/check_docs.py         # 链接、锚点、未引用的截图
python3 scripts/check_repo_files.py   # 没有符号链接、构建产物或超过 3 MB 的文件
```

截图尽量控制在几百 KB 以内（PNG）；更大的图先压缩。
