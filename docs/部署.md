# 部署管理后台

推荐用 Docker：一台装了 Docker 的 Linux 服务器加一个域名，几分钟就能跑起来，HTTPS 证书自动申请。不想用 Docker 的话，看文末的「手动部署」。

## 准备

- Linux 服务器（1 核 2 GB 起；要在后台打包 APK 的话 4 核 8 GB 起），安装 Docker 和 Docker Compose 插件。
- 一个域名，A 记录解析到服务器 IP。
- 服务器防火墙放行 80 和 443 端口（Caddy 申请证书要用 80）。

## 两种镜像

| 镜像 | 包含 | 大小 |
| --- | --- | --- |
| `slim`（默认） | 云控、卡密、小程序发布与热更新、告警、备份 | 约 250 MB |
| `full` | slim 的全部，加 JDK 17、Android SDK、Python 3.10，可以在后台打包 APK 和开启代码保护 | 约 2.5 GB |

只做云控和卡密用 slim 就够了。APK 也可以在自己电脑上用 `backend/xscript_pack.py` 打包。

## 启动

```bash
git clone <仓库地址> xscript && cd xscript/deploy
cp .env.example .env
vi .env                      # 填 XSCRIPT_DOMAIN 和 XSCRIPT_ADMIN_PASSWORD
docker compose up -d --build
docker compose logs -f xscript
```

浏览器打开 `https://你的域名/`，用 `.env` 里的账号登录。登录后马上做三件事：

1. 右上角头像 → **账号与令牌**：改密码，开启 **两步验证**。
2. **系统设置 → 基本**：服务器公网地址填 `https://你的域名`。打包出来的 App 用它激活卡密、连云控、检查热更新，发布 App 后不要再改。
3. **系统设置 → 安全**：打开「要求管理员开启两步验证」。

设备连接地址是 `wss://你的域名/ws?token=<设备密钥>`。App 会改用 `Authorization: Bearer` 请求头发送密钥，后台日志里 `?token=` 的值一律显示为 `***`。反向代理（nginx / Caddy）的访问日志默认会记录完整地址，旧版 App 仍把密钥放在地址里，建议在代理上关掉 `/ws` 的访问日志或去掉查询串。

`XSCRIPT_ADMIN_PASSWORD` 只在数据卷为空、第一次启动时用来创建管理员。之后改 `.env` 不会改已有账号的密码。

## 数据和备份

所有数据都在 Docker 卷 `xscript-data` 里（容器内 `/data`），包括数据库、**卡密签名私钥**、小程序、打包产物和自动备份。**私钥丢了，已经发布的 App 就再也无法激活和更新。**

后台每天凌晨 4 点自动备份到 `/data/backups`。备份要复制到别的机器才算真正的备份：

```bash
# 立即备份并复制出来
docker compose exec xscript xscript-server backup --out /data/backups/manual.tar.gz
docker compose cp xscript:/data/backups/manual.tar.gz ./

# 恢复（先停服务）
docker compose stop xscript
docker compose run --rm -v "$PWD/manual.tar.gz:/tmp/b.tar.gz:ro" xscript restore /tmp/b.tar.gz --force
docker compose start xscript
```

## 升级

```bash
docker compose exec xscript xscript-server backup     # 先备份
git pull
docker compose up -d --build
```

新版本第一次启动会自动升级数据库结构。如果数据库比程序版本新（回退了版本），服务会拒绝启动，不会损坏数据。

## 常用命令

```bash
docker compose exec xscript xscript-server reset-password admin               # 忘记密码（会提示输入）
docker compose exec xscript xscript-server reset-password admin --totp-only   # 手机丢了，关闭两步验证
docker compose exec xscript xscript-server reset-allowlist                    # 被登录 IP 白名单锁在外面，清空名单
docker compose exec xscript xscript-server device-key --name 渠道A            # 命令行生成设备密钥
docker compose logs --tail 200 xscript                                        # 看日志
```

## APK 打包（full 镜像）

`.env` 里设 `XSCRIPT_IMAGE_TARGET=full`，再 `docker compose up -d --build`。第一次打包要下载 Gradle 依赖和 Python 包，大约 5–10 分钟，缓存放在 `/data/.gradle`，之后会快很多。

正式签名：把 `release.jks` 放进 `deploy/secrets/`，取消 `docker-compose.yml` 里 `XSCRIPT_KEYSTORE` 那几行和卷挂载的注释，在 `.env` 里加 `XSCRIPT_STORE_PASS`、`XSCRIPT_KEY_PASS`。

打包会在服务器上执行用户上传的工程代码，只把操作员角色分给可信的人。

## 安全清单

- 管理后台只通过 Caddy 的 443 对外，`xscript` 容器不映射端口。
- 管理员开启两步验证，并在系统设置里强制要求。
- 按渠道或客户分别建设备密钥，泄露时停用一个就行。
- 备份文件里有签名私钥，存放位置要设访问权限。
- `/license/*`（卡密激活）和 `/pub/*`（热更新、分享下载）是公开接口，已按 IP 限流。

## 手动部署（不用 Docker）

需要 Python 3.10+ 和 Node 20+：

```bash
python3 -m venv .venv && .venv/bin/pip install -e backend
(cd backend/web && npm ci && npm run build)
.venv/bin/xscript-server init --data /srv/xscript-data
.venv/bin/xscript-server serve --data /srv/xscript-data --port 8765 --behind-proxy
```

前面用 nginx 或 Caddy 反向代理到 `127.0.0.1:8765`，WebSocket 路径 `/ws` 要允许升级并关闭读超时。可以参考 `deploy/Caddyfile`。用 systemd 守护进程时，把密码类环境变量放在 `EnvironmentFile` 里，不要写进命令行。
