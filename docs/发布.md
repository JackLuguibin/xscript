# 发布流程

一次发布同时给出 **App（APK）** 和 **VS Code 插件（vsix）**，用同一个版本号、同一个 Git 标签、同一个 GitHub Release 页面。流程由 `scripts/release.sh` 固化，每一步都可以单独重跑。

## 版本号策略

- 版本号 `X.Y.Z`；Git 标签 `vX.Y.Z`；`android/app/build.gradle.kts` 的 `versionName`；`ide/vscode-extension/package.json` 的 `version` 四处一致。`versionCode` 每次发布加 1。
- **插件版本 = App 发布版本**。这样 `xscript-vscode-0.2.5.vsix` 一定来自 Release v0.2.5，用户不用对照两套版本号。两者的版本号在发布之间不单独增长（没有发布就没有新版本号）。
- 一致性由 `scripts/release.sh check` 检查，`scripts/verify.sh` 会跑它，不一致就失败。
- 插件不上架 VS Code 应用市场，只放在 GitHub Release（`code --install-extension xscript-vscode-X.Y.Z.vsix`）。以后要上架，用同一个 vsix 和 `vsce publish`，版本号规则不变。
- v0.2.4 及更早的 Release 没有 vsix；从下一个发布起每个 Release 都附带。

## 步骤

```bash
# 0. 在 main 上，verify.sh 全绿；CHANGELOG.md 的「未发布」里是这次要发的内容
bash scripts/verify.sh

# 1. 升版本：改 versionName / versionCode、插件版本（含 package-lock）、README 里的下载链接，
#    并把 CHANGELOG 的「未发布」改成「vX.Y.Z（日期）」。只改文件，不提交
bash scripts/release.sh prepare 0.2.5
git diff                                   # 检查
git commit -am "chore(release): v0.2.5" && git push

# 2. 构建（签名 APK 需要 keys/release.properties；脚本不会打印或复制它）
bash scripts/release.sh build              # 只要 vsix：加 --skip-apk
#    产物在 dist/release/：
#      xscript-v0.2.5-release.apk
#      xscript-vscode-0.2.5.vsix
#      SHA256SUMS                          （两个文件各一行：sha256  文件名）

# 3. 在真机或模拟器上装 APK 做一次冒烟；在真实 VS Code 里装 vsix：
#      bash ide/vscode-extension/scripts/vscode-host-test.sh     # 隔离配置，不弹登录

# 4. 发布：先 dry run 看它要做什么，再加 --yes
bash scripts/release.sh publish
bash scripts/release.sh publish --yes      # 要求工作区干净、HEAD == origin/main、标签不存在、SHA256SUMS 与文件一致
```

`publish --yes` 会在已推送的 HEAD 上创建标签 `vX.Y.Z` 并 `gh release create`，附上 APK、vsix 和 `SHA256SUMS`，Release 说明取自 CHANGELOG 的该版本小节。不会修改已有的 Release。

## 用户怎么校验

```bash
shasum -a 256 -c SHA256SUMS --ignore-missing    # 下载了哪个文件就校验哪个
```
