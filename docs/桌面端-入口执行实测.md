# 设备如何执行工程入口（P0 实测）

> 对应 [桌面端设计 §10.2 / §12.1 P0-④](桌面端设计.md)。结论来自 **源码阅读 + 在两台模拟器上的实测**（2026-10-16）：
> 模拟器 5554（API 37，16 KB 页）和 5556（API 34，4 KB 页），App 版本 0.2.6，Python 3.10.19（Chaquopy）。两台结果**完全一致**。
> 复现：`adb forward tcp:19860 tcp:9860`，然后 `python desktop/app/tools/entry_probe.py --device localhost:19860 --burst 20000`。
> 工具只创建、运行、删除名为 `xsprobe_*` 的临时工程；不安装/卸载应用，不清日志，不动其它工程。

## 1. 一句话结论

**设备不是"运行 `__init__.py` 这个文件"，而是把工程目录当作 Python 包去 `import`。** 所以：

- `__name__` 等于**工程名**（不是 `"__main__"`），`if __name__ == "__main__":` 里的代码**不会执行**；
- 桌面端生成的入口存根必须在 `__init__.py` 顶层**直接调用** `main()`；
- 工程里的包导入可用，但**要统一用一种写法**，否则同一个文件会被导入两次。

## 2. 执行路径（源码）

1. HTTP `POST /projects/{name}/run`（或云控/定时/开机）→ 主进程启动 **独立的 `:script` 进程**（`ScriptService.kt`）。
2. `:script` 进程里起一个 Java 线程 `xscript-project`，调用 Python `xscript.runtime.runner.run_project(<工程目录>, <启动参数 JSON>, <是否调试>)`（`android/python-runtime/xscript/runtime/runner.py`）。
3. `run_project`：
   1. 把 `sys.stdout/stderr` 换成按行写入设备运行日志的流；
   2. `sys.path.insert(0, 工程目录)` 再 `sys.path.insert(0, 工程目录的父目录)` ——所以**父目录 `projects/` 排在最前，工程目录第二**；
   3. `os.chdir(工程目录)`；
   4. 从 `sys.modules` 删掉同名旧模块，打印 `xscript: starting <name>`；
   5. 激活运行时 pip 包；有 `requirements.txt` 就补装；
   6. **`importlib.import_module(<工程名>)`** ← 这就是"执行入口"；
   7. 等待**非守护**线程结束；打印 `xscript: finished <name>`。
   8. 不管怎么结束（正常、`sys.exit`、异常、被停止），最后都打印一行运行统计，例如 `xscript: 运行统计 用时 12.3s · 截图 45 次（平均 38ms）· 峰值内存 210MB`。截图次数统计 `capture*` / `find_*` 等真正向系统要画面的调用（`screen.cache` 冻结的帧不算），平均时间包括失败重试；峰值内存是 `:script` 进程的 VmHWM，每次运行都是新进程，所以就是这次运行的峰值。
4. 结束：`ScriptService.finish()` 通知主进程并 **`Process.killProcess`** 杀掉整个 `:script` 进程（脚本线程、悬浮窗、原生句柄都随进程消失）。
5. 入口文件判定：`__init__.py` 或 `__init__.pyc`（`ProjectStore.hasEntry`）。工程名规则：`[\p{L}_][\p{L}\p{N}_]*`（字母/下划线开头，字母数字下划线）。
6. zip 导入（`PUT /projects/{name}/zip`）：**只有一个顶层目录时会被剥掉**；解压后没有 `__init__.py` 直接拒绝。

## 3. 实测结果（两台模拟器一致）

探针工程 `__init__.py` 里打印自检信息，下面是设备返回的值（路径中的 `<N>` 是工程名）：

| 项 | 实测值 | 含义 |
| --- | --- | --- |
| `__name__` / `__package__` / `__spec__.name` | `xsprobe_entry`（都等于工程名） | 工程是**包**，不是 `__main__` |
| `__file__` | `/storage/emulated/0/Android/data/com.xscript.app/files/projects/<N>/__init__.py` | 绝对路径，用于 traceback |
| `__path__` | `[…/projects/<N>]` | 是包 |
| `os.getcwd()` | `…/projects/<N>` | 相对路径（如 `res/hello.txt`）按工程目录解析 ✅ |
| `sys.path[:4]` | `[…/files/projects, …/projects/<N>, <chaquopy>/app, <chaquopy>/requirements]` | 父目录最前，工程目录第二 |
| `sys.argv` | `['']` | 没有命令行参数 |
| `sys.modules['__main__'].__file__` | `None` | 没有 `__main__` 脚本 |
| 当前线程 | `Dummy-1`（`_DummyThread`），不是主线程 | 入口在 Java 创建的线程上跑 |
| `if __name__ == "__main__":` | **不执行** | 见 §1 |
| `from . import helper` | ✅ `helper-ok`，模块名 `<N>.helper` | 相对导入可用 |
| `import helper`（绝对，同一文件） | ✅ 可用，但模块名是 `helper`，**与 `<N>.helper` 不是同一个对象** | 混用会**导入两次**（模块级状态重复） |
| `from flows.daily import main; main()`（设计里的存根写法） | ✅ `flow-main-ran` | 原设计写法；**已改为相对导入**（见 §4-2：绝对导入会被兄弟工程遮挡） |
| `from .flows import daily` | ✅，模块名 `<N>.flows.daily`，与绝对导入的 `flows.daily` 不同对象 | **现采用此写法**（不会被兄弟工程遮挡） |
| 没有 `flows/__init__.py` 的命名空间包 | ✅ `namespace-ok` | 可用，但建议带 `__init__.py` |
| `xscript.runtime.runner.params()`（HTTP 运行） | `{}` | `/run` 端点**没有参数入口**（见 §4-5） |
| `res/hello.txt`（中文内容） | ✅ 正确读出 | UTF-8 没问题 |
| `sys.exit(3)` | 日志 `xscript: exit 3`，**没有** `finished` 行 | 退出码只出现在日志里 |
| 未捕获异常 | 日志里是完整 traceback，**没有** `finished` 行 | 见 §5 |
| `def main()` 定义了但入口没调用 | 只执行模块体，`main` 不会被自动调用 | 存根必须显式调用 |
| `\x1f` 控制字符（trace 前缀） | ✅ 在 `/logs` 里完整保留 | 设计 §7.6 的 `\x1fXF` 可行 |
| 线程：`threading.Thread(target=w).start()` 后入口返回 | `t.daemon` 是 **True**；入口一返回进程就被杀，**worker 的输出永远不会出现** | 见 §4-3 |
| 线程：`Thread(target=w, daemon=False)` | 日志 `xscript: waiting for thread Thread-1 (w)`，worker 跑完后才 `finished` ✅ | 并行节点要这样写 |

## 4. 对设计的影响（已写回设计文档 §10.2 与 R12）

1. **入口存根**：`__init__.py` 只放顶层调用，**不要** `__main__` 守卫：
   ```python
   # <project>/__init__.py  (由桌面端生成；相对导入，见下面第 2 条)
   from .flows.daily_signin import main
   main()
   ```
   `flows/daily_signin.py` 里是 `def main():`（生成物）。`xscript.android` 的导入放在 `main` 里面还是文件头都可以。
2. **统一用包内相对导入 `from .flows.<名字> import …`**（**2026-10-16 更正**：本条原先建议绝对导入。后续实测发现设备把 `<files>/projects` 放在 `sys.path` 最前，设备上若另有一个叫 `flows` 的兄弟工程，绝对导入 `import flows.daily` 会拿到**它**的文件；相对导入得到的是 `<工程名>.flows.daily`，不受影响。见 [设计 §14.8](桌面端设计.md)）。同一工程内不要两种写法混用（会得到两份模块）。
3. **并行节点**（设计 §7.4"并行"）：线程默认是守护线程，入口返回就被杀。生成代码必须 `Thread(..., daemon=False)` 或显式 `join()`。
4. **工程名遮挡风险（2026-10-16 已实测，两台模拟器一致）**：工程名 `json`/`random`/`colorsys` 运行"成功"，但工程内 `import json` 得到的是工程自己（没有 `dumps`），标准库被遮挡。桌面端新建工程时拒绝与标准库/`xscript`/`ascript`/常用包同名的工程名（`xscript_desktop/services/project_names.py`，设计 §14.8）。工具：`app/tools/shadow_probe.py`、`shadow_probe2.py`。
5. **启动参数**：HTTP `/projects/{name}/run` 没有 body，`params()` 为 `{}`；只有云控 `app_run` 的 `param` 和 `xscript://run` 链接能传参（本次**未实测**这两条路径）。设计 §7.3 里"运行对话框填实例参数"在直连模式下需要换个办法（例如运行前把参数写进工程里的 `res/params.json`，或经链接/云控启动）——P1 决定。

## 5. 运行结束与错误的判断（桌面端 `run.end` 怎么做）

设备没有"退出码/结束原因"的接口，只能从 `/status.running` 和日志推断：

| 情形 | `/status.running` | 日志里的标志 |
| --- | --- | --- |
| 正常结束 | → `false` | `xscript: finished <名字>` |
| `sys.exit(n)` | → `false` | `xscript: exit n`（没有 `finished`） |
| 未捕获异常 | → `false` | `Traceback (most recent call last):` … 最后一行 `ValueError: …`（没有 `finished`） |
| 用户停止（*源码推断，未实测*） | → `false` | `xscript: stopped by user` |
| `:script` 进程崩溃（*源码推断，未实测*） | → `false` | `xscript: script process for <名字> died unexpectedly` |

**traceback 格式（source map 反查用）**：每一帧是 `File "<设备绝对路径>/projects/<名字>/flows/daily.py", line 3, in main`。去掉 `…/projects/<名字>/` 前缀就是工程内相对路径，行号就是生成物行号（**没有偏移**）。traceback 开头有约 9 行 runner/importlib 内部帧，解析时只取路径在工程目录下的帧。

## 6. 日志窗口（设计风险 R12 的实测）

- 每次运行日志**不会清空**，`seq` 单调递增；用运行前 `GET /logs?since=0` 的 `next` 当起点即可只读本次运行。每次运行以 `xscript: script process start <名字>` 开头。
- 日志文件上限 2 MiB，超出后只保留尾部约 512 KiB（`LogBuffer.kt`，源码）。实测：一次打印 20 000 行（每行约 118 字节）后，`/logs` 只剩**最后 1 998 行**（`XSBURST 18002…19999`），前面的全部丢失；两台模拟器相同。**2026-10-16 补充**：打印 100 000 行 19 字节的短行（`\x1fXF\tenter\t…`）也只剩最后 1 998 行——可取回的窗口是**按行数（≈2 000 行）**，不是按字节；打印吞吐约 5 000–5 800 行/秒。
- 结论：**追踪模式（trace）的行必须节流**（每节点一行进出已经很多，循环里的节点要采样/合并），并且桌面端轮询要快于产生速度（>1 800 行/轮询间隔就会丢）；丢失时用 `seq` 不连续来检测并在 UI 里提示"追踪数据被截断"。
