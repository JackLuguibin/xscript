# XScript 桌面端 · 测试方案

> 状态：**P0 范围的测试已落地并在 macOS 上全绿；Windows 相关一律 ⚠ 未验证**。配套文档：[`桌面端设计.md`](桌面端设计.md)（尤其 §6 安全、§12.3 测试策略、§14 细化）、[`desktop/README.md`](../desktop/README.md)。
> 本文的"用例编号表"由 `desktop/app/tools/gen_test_matrix.py` **从测试源码生成**（CI 里 `--check`），不手写，所以不会和代码脱节。

标记：✅ 已实现且在 macOS 上跑过　📝 已设计未实现　⚠ 未验证（没有在该环境真正运行过）。

## 1. 目标与原则

1. **每个 P0 功能、每条已知错误路径都有自动化用例**：adb 缺失、设备离线/未授权、端口被占用、429、超时、坏 JSON、非 XScript 服务、LAN 非回环警告、截图未授权、进程被取消……
2. **不依赖真机也能全跑**：设备由 `FakeDevice`（确定性 HTTP 服务，可按需出错）和 `FakeAdb`/假 `adb` 脚本代替；真机/模拟器用例单独分层、默认跳过。
3. **测的是真实组合**：e2e 层用真实的 `QWebEngineView`（离屏）+ 真实构建的 React + `xsapp://` + QWebChannel + Python 服务，不是 mock 的浏览器。
4. **硬性安全约束写成测试**：前端不得联网（CSP + 源码扫描 + 页面内真实 `fetch/XHR/WebSocket` 被拦）、adb 只发白名单命令（永不 `uninstall`/`pm clear`/`shell`/`install`）、仓库里没有密钥文件。
5. **失败要能读懂**：用例有一句话说明（docstring），视觉回归失败时落盘实际图与差异图。

### 2.1 测试替身

| 替身 | 文件 | 做什么 |
| --- | --- | --- |
| `FakeDevice` | `desktop/app/tests/fake_device.py` | 确定性的设备 HTTP（固定 `/status`、渐变截图 PNG）。模式：`bad_json / non_object / html / empty / 429 / 500 / 503 / reset / slow`；`/screen` 另有 `503 capture_unavailable / bad / slow / 404`。记录请求。 |
| `FakeAdb` | `desktop/app/tests/conftest.py` | 内存里的 `adb`：`devices -l`、`forward`（自动分配端口）、`forward --remove`；记录调用，可断言"没有多余命令"。 |
| 假 `adb` 脚本 | `test_main_cli.py`、`test_adb_more.py` | 真的子进程（POSIX shell），用来测超时、退出码、stderr、spawn 失败、`--selftest --connect-adb` 全链路与清理。 |
| `mock_device` | `scripts/mock_device.py` | 仓库已有的功能型 mock（随机端口），用于 P0 的功能用例。 |
| `MemoryTransport` | `desktop/frontend/src/bridge/memory.ts` | 前端测试里代替 Python 一侧，可推送事件、记录请求。 |
| `harness.build_shell()` | `desktop/app/tests/harness.py` | 启动整套真实外壳（离屏），带 `js()/click()/wait_text()` 等"像用户一样操作"的辅助。 |

> 一个值得记下的坑（已写进 `harness.py`）：`QWebEngineUrlSchemeHandler` 没有 Python 持有者就会被垃圾回收，`xsapp://` 随之失效——页面永远 `about:blank`。工厂函数必须把 handler 存到返回对象上。

## 3. 怎么跑

```bash
# Python（离屏；需要先构建前端，否则 e2e/selftest/screenshot 用例自动跳过）
cd desktop/frontend && npm ci && npm run build
cd ../app && python -m pip install -e ".[test]"
python -m pytest -q                                   # 全部（默认跳过 device）
python -m pytest -q --cov --cov-report=term-missing   # 覆盖率（含子进程，pyproject 里 patch=["subprocess"]）
python -m pytest -q -m perf                           # 只跑性能预算
XSCRIPT_UPDATE_BASELINES=1 python -m pytest -m visual # 重新生成本平台的视觉基线
XSCRIPT_DEVICE_TESTS=1 python -m pytest -m device -v  # 真机/模拟器（只读 + adb forward，不卸载、不清数据）

# 前端
cd desktop/frontend && npm test                       # 单次
npm run test:coverage                                 # 带覆盖率与阈值（语句/行 85、函数 80、分支 75）

# 用例编号表
python desktop/app/tools/gen_test_matrix.py           # 重新生成本文第 11 节
python desktop/app/tools/gen_test_matrix.py --check   # CI：文档过期则失败
```

## 4. 错误路径矩阵（P0 必须覆盖）

"用户看到什么"以 [设计 §14.12](桌面端设计.md) 的错误码表为准；这里列**哪条用例守着它**。

| 场景 | 触发方式 | 期望（Python → 页面） | 守护用例 |
| --- | --- | --- | --- |
| adb 不存在 | 空 PATH、无 `ANDROID_HOME`、配置路径不存在 | `adb.not_found`；页面显示安装提示，**不**同时显示"没有设备" | `test_adb_missing_from_every_place`、`test_configured_path_that_does_not_exist_is_not_found`、E-04 |
| adb 命令失败 / 超时 / 起不来 | 假 adb 非零退出 / `sleep` / 不可执行 | `adb.failed`（带 stderr）/ `adb.timeout`（子进程被杀）/ `adb.spawn` | `test_real_subprocess_*`、`test_spawn_failure_is_adb_spawn` |
| 设备 `unauthorized` / `offline` / 不存在 | `FakeAdb` 状态 | `adb.not_ready` / `adb.no_such_device`；页面上按钮禁用；**没有创建 forward** | `test_adb_state_errors_have_distinct_codes`、E-01 |
| 端口被占用 / 本地端口越界 / 选项形序列号 | `forward` 的参数 | `adb.bad_port`、`adb.bad_serial`（拒绝 `-a`、`--help`）；设备端 9860 被占用时依次试 9861…9869 由**扫描**覆盖 | `test_forward_rejects_*`、`test_scan_finds_the_fake_and_skips_noise` |
| forward 建好了但 App 没开 | 端口上没人监听 | `device.unreachable`，**自己建的 forward 被移除** | `test_connect_adb_app_not_listening_removes_forward`、`test_selftest_connect_adb_unreachable_device_times_out_cleanly` |
| 设备返回坏 JSON / 非对象 / HTML（强制门户）/ 空体 | `FakeDevice.mode` | `device.protocol`，**不可重试**，没有半注册的设备 | `test_lan_connect_error_codes[...]`、E-06 |
| 429 / 503（可重试）、500（不可重试） | `FakeDevice.mode` | `device.http`，`retryable` 分别为 true/true/false | 同上 |
| 超时 | `FakeDevice` 慢响应 / `httpx.ReadTimeout` | `device.timeout`，可重试 | `test_lan_connect_timeout_is_device_timeout`、`test_timeout_maps_to_kind_timeout` |
| 连接被重置 / 拒绝 | `reset` 模式 / 端口 1 | `device.unreachable`，可重试 | `test_lan_connect_error_codes[reset-…]`、`test_nothing_listens_is_unreachable` |
| 对面是别的 JSON 服务（不是 XScript） | `/status` 是 `{"hello":"world"}` | `device.protocol`"不像 XScript 设备"，adb 路径下 forward 被移除 | `test_connect_address_rejects_a_non_xscript_json_server`、`test_connect_adb_to_non_xscript_server_removes_the_forward` |
| LAN 非回环地址 | 连 `192.0.2.77` | 连接成功但带"没有鉴权"警告；回环地址**没有**警告 | `test_non_loopback_lan_address_gets_the_unauthenticated_warning`、`test_loopback_addresses_get_no_lan_warning`、E-08 |
| 掉线又恢复 | 轮询期间 500 / 坏 JSON / 断连 | 状态 `offline`（带原因）→ 恢复 `online`，各推送一次事件 | `test_poll_goes_offline_on_each_failure_mode_then_recovers` |
| 截图：未授权录屏 | `/screen` 503 `capture_unavailable` | 页面显示"截图失败"，并提示授权；换新卡片不会命中缓存的旧图 | E-03、`screenshot: a failed image load…`（vitest） |
| 扫描范围过大 / 参数非法 | `10.0.0.0/8`、非列表 | `rpc.bad_params`；**立刻**拒绝，不先展开 1 600 万个地址 | `test_scan_rpc_range_error_maps_to_bad_params`、`test_lan_hosts_rejects_a_huge_range_instantly` |
| RPC 层畸形请求 | 非 JSON、数组、缺 method、params 非对象、>4 MiB | `rpc.parse / rpc.invalid / rpc.method_not_found / rpc.too_large`，`retryable=false`，不泄漏 traceback | `test_rpc_malformed_requests`、`test_oversized_request_rejected` |
| 取消 | `cancel` 请求 | 进行中的调用得到 `rpc.cancelled`；取消不存在的 id 静默 | `test_rpc_cancel_in_flight_request_yields_cancelled…` |
| 前端超时 / 中止 / 销毁 | `RpcClient` | `rpc.timeout`（并发 `cancel`）/ `rpc.aborted` / `rpc.disposed`；迟到的回复被忽略 | `client.test.ts` |
| Python 抛未预期异常 | handler 里 `raise` | `rpc.internal`，页面只看到类型与消息 | `test_unexpected_exception_is_internal_error_without_traceback` |
| 应用启动失败 | 页面 boot 抛错 | 红色 `role=alert` 提示"启动失败：…" | e2e（见 §8）📝 |

**镜像流的 2 观看者上限与 429**（设计 §14.4）：P1 才实现 `MirrorProxy`。已实测的槽位行为在设计里；测试计划是用 `httpx.MockTransport` 与自制 asyncio 流式服务器覆盖 429、无帧看门狗、断流重连、扇出（📝 随 P1）；**P0 不对真机开流**——在 5556 上开过流会泄漏槽位（设计 §14.4），所以真机层只做单次 `GET /screen`。

## 5. 安全检查表（S 层）

| 项 | 做法 | 用例 |
| --- | --- | --- |
| CSP：`connect-src 'none'`、`script-src 'self'`（无 `unsafe-eval`/`unsafe-inline`/远程）、`object-src/base-uri/form-action 'none'` | 解析 `CSP` 常量逐指令断言；CSP `<meta>` 注入在 `<head>` 最前 | `test_csp_*` |
| 页面真的不能联网 | 在真实外壳里执行 `XMLHttpRequest`/`fetch`/`WebSocket` 到设备端口，期望被拦 | `test_page_cannot_make_network_requests_csp` |
| 前端源码里没有联网原语 | vitest（`no-direct-network`）+ Python 的静态扫描（`fetch(`、`XMLHttpRequest`、`WebSocket`、`EventSource`、`sendBeacon`、`importScripts`、`serviceWorker`） | `test_frontend_source_has_no_network_primitives` |
| 没有危险 HTML/eval | 扫描 `dangerouslySetInnerHTML`、`eval(`、`new Function(`、`innerHTML =`、`document.write` | `test_frontend_never_uses_dangerous_html_or_eval` |
| 构建产物无远程源 | 扫描 bundle 里的 `http(s)://` | `test_built_bundle_contains_no_remote_origins` |
| 导航白名单 | 表驱动：`xsapp://app` ✓；`xsapp://evil`、`xsapp://app.evil.com`、`http(s)`、`file`、`javascript`、`data`、`chrome`、`view-source` ✗；dev 模式只放行 dev 源 | `test_navigation_allow_list_table`、`test_dev_url_allows_only_its_own_origin` |
| 外部链接去系统浏览器、`window.open` 不开新窗 | 真实外壳里点击 | `test_navigation_guard_blocks_external_and_unknown` |
| 路径穿越 | 10 种拼写（`..`、`%2e%2e`、`%5c`、NUL、`//etc/passwd`、符号链接逃逸…） | `test_resolve_static_blocks_every_traversal_spelling`、`test_resolve_static_blocks_symlink_escape` |
| scheme 只服务 GET、只认 `app` 主机 | 真实外壳里请求未知路径 | `test_scheme_rejects_unknown_paths` |
| 设备流量不走系统代理 | `trust_env=False`，设置 `HTTP_PROXY` 后仍为 False | `test_device_client_ignores_proxy_environment` |
| adb 只发白名单命令 | 源码里没有 `uninstall/install/shell/clear/pm/push/pull/reboot/root`；`_run([...])` 首参只能是 `version/devices/forward/-s`；子进程全链路记录 adb 调用并断言 | `test_adb_service_only_ever_builds_whitelisted_commands`、`test_selftest_connect_adb_reports_device_and_removes_its_forward` |
| 只删自己建的 forward | 外部 forward 不会被 `remove_forward` 碰 | `test_never_removes_foreign_forwards` |
| 密钥不入库 | `git ls-files desktop docs` 里没有 `keys/`、`.jks/.keystore/.pem/.p12/.key` | `test_no_secret_material_is_tracked_under_desktop` |
| 请求体上限 | 4 MiB | `test_oversized_request_rejected` |

⚠ **已知并接受的边界**：设备 API 本身没有鉴权（设计 §6.1）；`device.scan` 的 `hosts` 由页面传入（≤1024 个，仍只在本机 Python 里发起，页面自己仍不能联网）。**P1 引入 Monaco 时需要 `worker-src`**（设计 §14.3）——那时 CSP 测试要同步放宽到恰好需要的那一条，并保持其余断言。

## 6. 视觉回归（V 层）

- 工具：`tests/visual_util.py`，`window.grab()` 截图，QImage 逐像素比较（每通道差 >12 才算不同，不同像素占比 ≤0.2% 通过）。
- **基线按平台存放**：`tests/baselines/darwin|linux|win32/`。字体光栅化各系统不同，**不跨平台比较**；没有本平台基线就跳过（不是通过）。
- 更新基线：`XSCRIPT_UPDATE_BASELINES=1 pytest -m visual`，并人工看过新图再提交。失败时 `tests/_visual_out/<name>.actual.png|diff.png`。
- 场景（亮/暗两套主题）：空状态、列出 adb 设备（就绪/未授权/离线）、已连接的设备卡片（含截图预览）、adb 缺失错误态、截图失败态、640/480 px 窄窗口。共 10 张，基线在 `desktop/app/tests/baselines/darwin/`（已提交）；`test_visual_util.py` 测比较器本身（相同/小噪声/不同/无基线/更新）。
- 基线内容是 `FakeDevice` 的固定数据 + 固定窗口尺寸，不含时间戳/随机值。
- ⚠ Linux CI 与 Windows：**没有基线**，所以只在 macOS 上有视觉回归（CI 里这 10 个用例是 skipped）；Linux 基线可以以后在 CI 里生成后提交（📝）。

## 7. 性能预算（P 层）

上限是故意放宽的（CI 机器慢且抖），目的是抓"误写成 O(n²)/阻塞事件循环"：5 000 次 RPC 调度 <3 s；解析 5 000 行 `adb devices` <1 s；`/8` 扫描范围 <0.2 s 内拒绝（**曾经要 ≈10 s**，本轮修复）；20 次串行截图、50 并发 `/status` 各 <5 s；轮询 20 台设备时事件循环心跳间隔 <0.5 s；本机空端口扫描 <3 s。真机上的数字（`/screen`、流吞吐）在设计 §14.1/§14.4，不进自动化。

## 8. 端到端（E 层）要点

真实外壳 + 真实构建的前端，设备是 `FakeDevice`，adb 是 `FakeAdb`，**一个窗口跑整个模块**（QtWebEngine 的 profile 创建/销毁昂贵且顺序敏感），每个用例前重置状态并重载页面。覆盖：首屏与 adb 列表、连接/断开与 forward 清理、截图成功/失败、adb 缺失提示、各类坏响应的错误条（参数化）、LAN 警告、扫描、轮询掉线/恢复的推送事件、窗口缩放。**本轮由 e2e 发现并修复的真实缺陷**：截图 URL 用卡片内计数器（从 1 开始）当缓存破坏参数，新建卡片会命中 Chromium 缓存的**上一次会话**的图——失败的截图可能显示成功的旧图；改为单调时间戳。

## 9. Windows 专项清单（全部 ⚠ 未验证）

自动化里只有 **逻辑模拟**（`test_windows_sim.py`：候选 adb 路径顺序与 `.exe`、`%LOCALAPPDATA%` 数据目录、`CREATE_NO_WINDOW` 参数、保留名 `CON/NUL/COM1/LPT9`、UNC/IPv6 目标不崩溃）。这些**不是** Windows 验证。真机清单是设计 [§14.9 W-01…W-18](桌面端设计.md)（adb 路径、窗口闪烁、WebView2/QtWebEngine 差异、DPI 缩放、长路径、防火墙对 9860 的提示、安装包与更新、读屏…），需要在 `windows-latest` 或真机上逐条执行，当前**一条都没跑**。

## 10. CI

`.github/workflows/ci.yml` 的 `desktop` 作业（ubuntu-24.04，Python 3.10，Node 22）：

1. `npm ci` → `typecheck` → `test:coverage`（阈值见上）→ `build`
2. 安装 QtWebEngine 的系统库
3. `pytest --cov`（含 e2e/子进程/安全/性能，视觉与 device 自动跳过）
4. `python desktop/app/tools/gen_test_matrix.py --check`
5. `python -m xscript_desktop --selftest`

⚠ Linux CI 的离屏 QtWebEngine 与本机 macOS 有差异（沙箱、GPU、字体）；`--no-sandbox --disable-gpu` 已在作业环境里设置。视觉回归、真机用例、Windows 都不在 CI 里。
