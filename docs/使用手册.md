# XScript 使用手册

这份手册说明每个系统从哪里进入、怎么打开、第一次使用要做什么。更细的接口和参数见文末的“深入文档”。

下面的命令以 MuMu 模拟器（adb 地址 `127.0.0.1:16384`）为例；用真机时把 `-s 127.0.0.1:16384` 换成真机的序列号，或者只接一台设备时直接去掉。

## 总览：六个入口

| 系统 | 在哪里打开 | 地址 / 命令 | 用途 |
| --- | --- | --- | --- |
| 手机 App 首页 | 手机桌面 → XScript | — | 授权、选择运行模式、运行和管理小程序 |
| 网页开发工具 | 电脑浏览器 | `http://127.0.0.1:9860/tools/` | 图色工具、标注工具、投屏 |
| Cursor AI 编程 | Cursor 的 MCP | `.cursor/mcp.json` 里的 `xscript` | 让 AI 看屏幕、写脚本、上传、运行、看日志 |
| 云控后台 | 电脑浏览器 | `http://<服务器>:8765/?token=<token>` | 管理多台设备：批量启动、截图、发消息、分组、定时 |
| 卡密管理 | 电脑终端 | `scripts/xscript_license.py` | 生成、查看、停用卡密 |
| APK 打包 | 电脑终端 | `scripts/xscript_pack.py` | 把一个小程序打包成独立 App |

前两个入口每次使用前都要让电脑能访问到手机（第 2 节）。云控后台需要先在电脑上启动服务端（第 5 节）。

## 1. 手机 App 首页

### 安装

```bash
./scripts/build_android.sh
adb -s 127.0.0.1:16384 install -r android/app/build/outputs/apk/debug/app-debug.apk
```

打开桌面上的 **XScript**。

### 第一次使用：逐项授权

首页从上到下每一行都可以点：

| 行 | 作用 | 怎么开 |
| --- | --- | --- |
| 开发者地址 | 显示 `http://<手机IP>:<端口>/`，点一下复制 | 不用设置。端口默认 9860，被占用时顺延到 9869 |
| AI 编程连接 | Cursor 连上后显示“已连接” | 见第 3 节 |
| 运行模式 | Root 或无障碍 / 仅无障碍 / 仅 Root | 一般保持默认 |
| 悬浮窗权限 | 运行时的悬浮停止按钮、脚本的悬浮窗 | 点进去打开“允许显示在其他应用上层” |
| Root 权限 | 有 root 时手势、截图更稳 | 点一下，在 root 管理器里允许 |
| 图色权限 | 系统录屏截图，最快 | 点一下，在弹窗里选“立即开始” |
| 云端控制 | 连接云控服务器 | 见第 5 节 |
| 小程序列表 | 进入工程列表 | 见下文 |
| 辅助权限管理 | **无障碍服务，必须开** | 点进去 → 已下载的应用 → XScript → 打开 |
| 通知使用权 | 脚本监听通知时需要 | 点进去打开 XScript |
| 文件访问权限 | 读写 `/sdcard` 里的文件 | 点进去允许 |
| 后台运行 | 防止系统杀后台 | 点进去选“不限制” |

模拟器上可以用 adb 一次开好无障碍和悬浮窗：

```bash
adb -s 127.0.0.1:16384 shell settings put secure enabled_accessibility_services com.xscript.app/com.xscript.app.a11y.XscriptAccessibilityService
adb -s 127.0.0.1:16384 shell settings put secure accessibility_enabled 1
adb -s 127.0.0.1:16384 shell cmd appops set com.xscript.app SYSTEM_ALERT_WINDOW allow
```

（第一行会覆盖已开启的无障碍服务列表。）

### 小程序列表

首页 → **小程序列表**：

- 右上角 **新建**：新建一个空工程（名字必须是合法的 Python 标识符，可以用中文）。
- 右上角 **导入**：从 zip 导入，或从 AScript（`/sdcard/airscript/model`，需要 root）导入。
- 点某个小程序进入详情页，可以：运行 / 停止、看日志、打开 **开机自启** 和 **停止后重新运行**、添加 **定时任务**、查看和编辑文件、删除。

首页顶部的卡片显示上次运行的小程序，右侧按钮直接运行或停止。右上角 **日志** 查看所有运行输出。

## 2. 让电脑访问手机

网页开发工具和 Cursor 都通过 HTTP 访问手机上的 XScript。

### USB / 模拟器（推荐）

```bash
adb connect 127.0.0.1:16384                         # 只有 MuMu 需要
adb -s 127.0.0.1:16384 forward tcp:9860 tcp:9860    # 端口以首页“开发者地址”为准
curl http://127.0.0.1:9860/status                   # 返回设备 JSON 就说明通了
```

**模拟器重启、adb 重启后 forward 会失效，需要重新执行这两条命令。** 这是连不上时最常见的原因。

### 局域网

手机和电脑在同一个 Wi-Fi 下时，直接用首页“开发者地址”里的 IP，例如 `http://192.168.1.23:9860/`。

> 这个接口没有任何鉴权，同一网络里的任何人都能在手机上运行代码。只在可信网络里使用，不确定时用 USB。

## 3. Cursor AI 编程（MCP）

### 第一次配置

```bash
python3.12 -m venv .venv && .venv/bin/pip install -e mcp-server -e python-stubs
```

仓库里的 `.cursor/mcp.json` 已经配置好 `xscript` 服务，默认连接 `127.0.0.1:9860`（配合第 2 节的 adb forward）。用局域网 IP 时改 `XSCRIPT_DEVICE`。

然后在 Cursor 里打开 **Settings → MCP**，确认 `xscript` 是开启状态（绿色）。第一次或改过配置后，关掉再打开一次。

### 使用

在 Cursor 对话里直接说需求，例如“打开设置，搜索 WLAN 并点进去，写成一个小程序”。AI 会先截图、读控件树，再写脚本、上传、运行、看日志。手机首页的“AI 编程连接”会显示“已连接”。

常用工具（AI 会自动调用，也可以点名让它用）：

- 看设备：`get_device_status`、`screen_capture`、`dump_ui_tree`
- 工程：`upload_directory`、`run_project`、`stop_project`、`get_run_log`
- 图色调试：`take_snapshot` → `vision_test`（找色、比色、找图、OCR、YOLO）→ `crop_template`
- 模型和包：`upload_model`、`pip_install`、`pip_list`
- 运行选项：`project_run_options`、`add_schedule`

### 连不上时

1. 先在终端 `curl http://127.0.0.1:9860/status`。不通就重做第 2 节的 forward。
2. `curl` 通但 Cursor 不通：在 MCP 设置里把 `xscript` 关掉再打开，错误信息在 **Output → MCP Logs**。

## 4. 网页开发工具（图色 / 标注 / 投屏）

完成第 2 节后，电脑浏览器打开：

```
http://127.0.0.1:9860/tools/
```

页面由手机上的 App 提供，不用安装任何东西。顶部导航栏可以在三个工具之间切换。

### 图色工具

先点 **截图** 冻结一帧，之后所有取色、测试都基于这一帧。滚轮缩放，按住空格拖动画面。

- **取色**：点击图片添加颜色点，右侧生成 `x,y,#RRGGBB|...`，可以一键复制 `FindColors.find(...)` / `CompareColors.compare(...)` 代码（AScript 或 XScript 写法）。
- **框选**：拖动框出区域，可以复制成 `rect`，或者存为工程里的模板图片（`res/img/...`）。
- **测试**：多点找色、多点比色（逐点显示期望值和实际值）、找图、OCR。用的是和脚本完全相同的引擎，结果直接画在图上。

### 标注工具

用来做 YOLO 训练数据。

1. 新建数据集，填写类别。
2. **截图加入** 当前屏幕，或上传图片。
3. 拖动画框；数字键 1–9 切换类别，A / D 切换上一张 / 下一张，Delete 删除选中的框。自动保存。
4. **导出 YOLO** 下载训练包（`images/`、`labels/`、`data.yaml`）。

训练和部署到手机：

```bash
yolo detect train data=data.yaml model=yolo11n.pt imgsz=640
yolo export model=runs/detect/train/weights/best.pt format=onnx imgsz=640
```

把 `best.onnx` 放进工程的 `res/`，脚本里 `yolo.load(R.res("best.onnx")).detect()`。

### 投屏

实时显示手机画面。在画面上点击就是点击手机，拖动就是滑动，下方按钮是 返回 / 主页 / 最近任务。授予“图色权限”后帧率明显更高；只用 root 截图时约 2 fps。

## 5. 云控后台

用来同时管理多台设备（手机不需要和电脑在同一网络）。

### 启动服务端

第一次安装依赖：

```bash
.venv/bin/pip install aiohttp==3.14.3 cryptography
```

启动（`--token` 换成你自己的长随机字符串）：

```bash
.venv/bin/python scripts/xscript_cloud.py --port 8765 --token 你的token
```

需要在线卡密时再加两个参数（见第 6 节）：

```bash
.venv/bin/python scripts/xscript_cloud.py --port 8765 --token 你的token \
    --licenses licenses.db --key keys/private.pem
```

服务端在终端里前台运行，关掉终端就停止。分组和定时任务保存在 `xscript_cloud_state.json`，重启后还在。

### 打开控制台

浏览器打开 `http://<服务器IP>:8765/?token=你的token`（本机就是 `http://127.0.0.1:8765/?token=你的token`）。

### 让设备连上来

手机 XScript 首页 → **云端控制** → 填：

```
ws://<服务器IP>:8765/ws?token=你的token
```

点 **连接**，首页显示“已连接”后，控制台的设备列表里就会出现这台设备。

- **模拟器连本机服务端**：先执行 `adb -s 127.0.0.1:16384 reverse tcp:8765 tcp:8765`，地址填 `ws://127.0.0.1:8765/ws?token=...`。
- **公网服务器**：前面加 nginx / Caddy 做 TLS，设备端改用 `wss://`。
- 打包出来的 App 可以在打包时用 `--cloud-url` 预置地址，首次启动自动连接。

### 控制台怎么用

1. 顶部 **目标** 选择：全部设备 / 某个分组 / 某台设备。
2. **启动**：填小程序名（和可选的 JSON 参数，脚本里用 `system.params()` 读取），点启动。
3. **停止**、**截图**、**主页**、**返回**：对目标设备执行。
4. **消息**：发给正在运行的脚本（脚本里用 `cloud.on_message` 接收）。
5. 设备列表里 **分组** 按钮修改分组；“脚本数据”一列显示脚本 `cloud.send()` 上报的内容。

定时任务和其他批量操作通过 REST API 完成，见 [CLOUD.md](CLOUD.md)。

> 拿到 token 的人能控制所有在线设备。token 要足够长，不要写进公开的代码仓库。

## 6. 卡密管理

没有网页界面，在电脑终端里操作。下面的命令都在仓库根目录执行。

### 第一次：生成密钥

```bash
.venv/bin/python scripts/xscript_license.py keygen --out keys/
```

生成 `keys/private.pem`（私钥）和 `keys/public.b64`（公钥）。**私钥要保密并备份**：泄露了别人可以伪造授权，丢了就无法再签发。不要提交到 git。

### 日常操作

```bash
L=".venv/bin/python scripts/xscript_license.py"
$L cards  --db licenses.db --count 50 --days 30 --app com.me.game   # 生成 50 张 30 天卡（0 = 永久）
$L list   --db licenses.db                                          # 查看状态、绑定设备、到期时间
$L revoke --db licenses.db XS-XXXX-XXXX-XXXX-XXXX                   # 停用
$L unbind --db licenses.db XS-XXXX-XXXX-XXXX-XXXX                   # 解绑，允许换设备（到期时间不变）
$L issue  --key keys/private.pem --device <设备ID> --days 30        # 离线授权码（不需要服务器）
```

- 在线卡密需要第 5 节的服务端带着 `--licenses licenses.db --key keys/private.pem` 运行，打包时用 `--license-server` 指向它。
- 卡密在第一次激活时绑定设备，有效期从激活开始算。
- 停用后，App 最多 6 小时内联网复核时失效。

### 用户那边怎么激活

打开打包的 App → **卡密授权** → 输入卡密 → **激活**。对话框里显示本机的设备 ID，离线授权时把它发给你。

## 7. APK 打包

在仓库根目录执行（需要和构建 XScript 相同的环境）：

```bash
.venv/bin/python scripts/xscript_pack.py 你的工程目录 \
    --app-id com.me.game --name "我的脚本" --icon icon.png \
    --version 1.0.0 --version-code 1 --abis arm64-v8a \
    --license-key keys/private.pem --license-server https://你的服务器:8765 \
    --cloud-url "wss://你的服务器:8765/ws?token=你的token" \
    --out dist/
```

生成的 APK 在 `dist/`。只打 `arm64-v8a` 时约 77 MB。发布更新时增大 `--version-code`；正式发布要用 `--keystore` 签名，否则无法覆盖升级。

打包出来的 App 打开后是一个简化界面：启动 / 停止按钮、卡密授权、需要的权限（无障碍、悬浮窗、截图、Root、后台运行）、云控状态、设备 ID。它没有开发者首页和局域网调试接口（加 `--dev-server` 才有）。

注意：打包的 App 是独立应用，**无障碍服务要单独为它开启**，和 XScript 本身的授权互不影响。

## 常见问题

**网页工具 / Cursor 突然连不上了**
模拟器或 adb 重启过，重新执行 `adb connect` 和 `adb forward`（第 2 节）。

**首页“云端控制”一直显示“重连中”**
服务端没在运行，或者地址 / token 不对。确认服务端终端还开着，用浏览器打开控制台地址试一下。模拟器连本机时别忘了 `adb reverse`。

**脚本点击没反应**
确认无障碍服务开着（首页“辅助权限管理”显示“已开启”）。仍然不行可以把运行模式切到 Root。

**OCR 在模拟器上识别不出来**
改用 PaddleOCR：`screen.ocr(engine="paddle")`，第一次会下载约 22 MB 模型。

**打包的 App 提示“未激活，请输入卡密”**
这是开启了卡密的正常状态，输入有效卡密即可；也可以通过云控 `app_run` 带 `card` 参数激活。
