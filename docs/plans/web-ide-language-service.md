# 网页 IDE 第二阶段：跳转到定义、基于解析器的检查

状态：草稿计划（docs/plans）。逐阶段实现，每阶段一个或几个小提交，推送到同一个草稿 PR。

## 范围

- 网页 IDE（手机 App 内的纯 JS 编辑器）在 #123 的悬停 / 参数提示之后，加：跳转到定义（工程内文件和 `xscript.*` / `ascript.*` 存根）、查找引用、基于真正 Python 语法解析的诊断（替代现在保守的括号/引号/冒号/缩进检查）。
- 约束：离线、无构建、无第三方依赖（和现有 `editor-*.js` 一致），手机浏览器能跑，400 KB 以内的文件不卡。
- 不做：类型推断、重构、Monaco。

## 依据

- `docs/功能对照.md` 网页 IDE 行：未实现 Monaco 级语言服务（类型推断、跳转、重构、真正的语法分析）。
- `editor-check.js` 只做保守检查；`editor-complete.js` 的 `scope()` 是按行正则。
- #123 已有 `editor-docs.js`（存根签名和文档），可作为定义跳转的「库」目标（只显示存根，不跳文件）。

## 分阶段清单

- [x] **D.1 词法+解析器**：`editor-parse.js`：Python 3.10 子集的递归下降解析器（语句、表达式、缩进），输出带位置的 AST 和语法错误；Node 单测覆盖 CPython 语法错误样例
- [ ] **D.2 诊断换成解析器**：`editor-check.js` 用解析器结果；保留现有提示文案；误报回归集
- [ ] **D.3 符号表**：模块级 / 函数级定义、import 绑定，跨工程文件（`/projects/<name>/files`）
- [ ] **D.4 跳转到定义**：F12 / Ctrl+点击：工程内跳到文件和行；库符号显示存根签名和文档
- [ ] **D.5 查找引用**：Shift+F12：当前工程内同一符号的引用列表
- [ ] **D.6 文档与截图**：使用手册、截图、ARCHITECTURE

## 测试计划

- Node 单测（解析器对照 `python3 -c 'import ast'` 的结果：同一批样例，错误行号一致）。
- headless Chrome DOM 测试（mock 设备）：F12 跳转、引用列表、诊断波浪线。
- 性能：400 KB 文件解析 < 100 ms（Node 基准测试，CI 只做宽松上限）。

## 风险

- 解析器体积（目标 < 60 KB 未压缩）。
